# 排序原则与里程碑

## 三条排序原则

1. **地基优先**：被别人依赖的先做。最难的项（GPU 后端）不等于最该先做——
   它依赖矢量图形与视觉回归两件事先就位，否则做完也没法证明「画对了」。
2. **风险前置**：与定位冲突的（GPU 后端 vs 零 cgo/单二进制）、需要选型的
   （文本整形 vs 是否引入 shaping 依赖），先写 RFC 拍板，别边写边想。
3. **静默失效优先**：凡是「看起来好了其实没画出来」的地方，优先补断言。
   本轮三个静默 bug 的教训是：**没有断言的功能等于没有做完**。

## 里程碑划分

| 里程碑 | 主题 | 包含 | 目标产出 |
|---|---|---|---|
| **M1 质量地基** | 先能证明对错 | 13、12 | 组件级截图 + 结构化断言框架；写死样式收编为令牌 |
| **M2 文本与输入** | 最难的一层 | 01、06、07、05 | 多语言 shaping + 回退链；三平台 IME；RTL；选区与撤销栈 |
| **M3 更新与规模化** | 结构与数量 | 08、09、10、11 | keyed diff；二维虚拟化；分数缩放；跨屏迁移不丢状态 |
| **M4 渲染与生态** | 性能与边界 | 03、02、04、14、15 | 渐变/特效；GPU 后端（可降级）；PDF 导出；插件沙箱；剖析器 |

## 关于「先做 M1」的理由

M1 只有两项，且都不难（★★★/★★★★），但它们决定后面 13 项能不能验收：

- 没有 13（视觉回归），M2 的 shaping 改完全局文字绘制后，无法判断
  「三平台都还对不对」——只能靠人肉看几十张截图，不可持续；
- 没有 12（令牌），M3/M4 里新增的视觉元素会继续往内核里写死新的颜色常量，
  等做换肤时又是一轮收编。

## 暂不推进（附理由）

| 项 | 理由 |
|---|---|
| 浏览器/WASM 目标 | 主仓已有 `docs/wasm-playground-feasibility.md` 的可行性结论，与桌面定位不冲突但收益未证 |
| 3D 渲染 | 依赖 02 且超出 GUI 范畴，暂不列入 |
| 自研 JS 调试协议 | 优先级低于插件沙箱（14），且 devtools 已有基础 |
