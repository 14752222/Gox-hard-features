# 04 — 打印与 PDF / 图片导出

- 分层：渲染 ｜ 难度 ★★★ ｜ 工作量 4–6 人周 ｜ 依赖：01、03

## 现状取证（主仓）

- 无打印 / 导出入口：`gx/*` 模块清单里没有 print / export。
- 但**离屏出图已具备**：`gfx/gallery_shot_test.go` 用假 Surface 渲染真实上屏帧并写 PNG
  （`shotsImage` + `png.Encode`），说明「把界面渲染到位图」这条链是通的。
- 字体子系统自研（`gfx/font.go`），没有现成的 PDF 字体嵌入经验可复用。

## 为什么难

1. **分页**：长文档要按可打印区域切页，且**行内元素不能被切断**（表格行、卡片、
   多行文本块），还要支持重复表头、页眉页脚、孤行寡行控制——本质是第二套布局约束。
2. **向量文本**：走位图导出很简单，但 PDF 里文本应该是**可选中、可搜索**的，
   需要字体子集化 + ToUnicode 映射，而字体子系统是自研的，没有现成工具链。
3. **打印通道**：Windows（XPS / GDI）、macOS（NSPrintOperation）、Linux（CUPS）
   三条路，且要零 cgo。
4. **单位与色彩**：pt / dp / px 三套单位，打印 DPI 与屏幕 DPI 不一致；
   色彩管理（sRGB / CMYK）要不要管到什么程度。
5. **与「所见即所得」的偏差**：打印媒体尺寸、边距、分页都会改变布局结果，
   需要一套「打印专用布局」而不只是缩放。

## 技术路线

1. PDF 导出（自写 PDF writer + 字体子集化，先位图后向量文本）；
2. 多页图片导出（缩放 / 选区 / 透明背景）；
3. 打印后端（三平台，先 macOS/Windows，Linux 走 CUPS 或 PDF 中转）；
4. 打印预览与分页控制属性（`breakBefore` / `repeatHeader` 一类）。

## 验收标准

- 生成的 PDF 能被主流阅读器打开，**文本可选中可搜索**（向量文本阶段）；
- 长文档分页不切断行内元素，表头重复；
- 三平台打印队列冒烟（无打印机时降级为生成 PDF）；
- 导出图片与屏幕所见一致（容差内）。

## 主要风险

| 风险 | 缓解 |
|---|---|
| PDF 字体子集化工作量大 | 分两阶段：先位图导出可用，再补向量文本 |
| Linux 打印链复杂 | 走「生成 PDF + 交给系统命令」的中转方案 |
| 分页规则引发布局分叉 | 明确打印布局是独立通道，不复用屏幕布局结果 |
