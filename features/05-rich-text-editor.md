# 05 — 富文本编辑

- 分层：输入 ｜ 难度 ★★★★★ ｜ 工作量 10–16 人周 ｜ 依赖：01、06、08

## 现状取证（主仓）

- `gfx/input.go` 文件头：**「v1 不做：选区与拖选（Shift+移动）、水平滚动
  （超长文本硬截断）、双击选中、IME 组合输入（P2-7）、剪贴板（P3-3）」**。
- `gfx/textarea.go` 是多行编辑器，但建立在上面这套单行输入的基础上，
  没有选区/撤销栈/富样式的公共层。
- 也没有「文本缓冲」这一层：组件直接持有字符串。

## 为什么难

1. **文本缓冲与索引**：万行文档下 `string` 拼接/切片是 O(n)，需要 rope / gap buffer
   或分段结构，并把「行号 ↔ 偏移」的索引维护出来。
2. **软换行与双向映射**：屏幕坐标 ↔ 字符偏移要逐行矩形查表；
   一旦上了 shaping（01）与 RTL（07），这个映射还要跨 cluster / 跨方向。
3. **选区渲染**：多行选区是若干矩形的并集，且要处理行末包含换行符、
   软换行续行、RTL 段的视觉顺序与逻辑顺序不一致。
4. **撤销 / 重做**：要把编辑操作建模为可逆的原子操作，并且与 **IME 组合期**
   合并（一次中文输入是一个操作，不是每个按键一个操作）——这也是它依赖 06 的原因。
5. **富样式**：片段（span）合并、样式继承、粘贴清洗（HTML / RTF / 纯文本）、
   与「脚本侧数据模型」的边界（谁持有真相）。
6. **性能与体验**：键入延迟、光标跟随滚动、长文档首次布局时间。

## 技术路线

1. 文本缓冲 + 行索引（纯文本，先不动样式）；
2. 选区与拖选（单行 → 多行）、键盘导航（词/行/段）；
3. 坐标 ↔ 偏移映射（软换行 + 折行矩形）；
4. 撤销 / 重做栈（含 IME 组合期合并）；
5. 富样式片段与粘贴清洗；
6. 大文档性能（增量布局 / 视口外不测量）。

## 验收标准

- 用例：拖选 / 双击选词 / Shift+方向 / Home-End / 上下跨行 / 软换行末行点击；
- 中文 IME 组合期间：不丢字符、撤销栈不产生碎步、光标位置正确；
- 万行文档键入延迟在帧预算内；
- 三平台剪贴板往返（复制/粘贴含样式与纯文本两种）。

## 主要风险

| 风险 | 缓解 |
|---|---|
| 与 shaping / RTL 交叉后返工 | 先定义好「偏移」的抽象（逻辑偏移 vs 视觉位置），不写死字节索引 |
| 撤销栈与 IME 时序错乱 | 依赖 06 落地后再做撤销合并 |
| 富样式与脚本数据模型的边界不清 | 明确「组件持有缓冲，脚本持有初始值」的单向流 |
