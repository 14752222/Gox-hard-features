# 03 — 矢量图形与视觉特效

- 分层：渲染 ｜ 难度 ★★★★ ｜ 工作量 6–10 人周 ｜ 依赖：13

## 现状取证（主仓）

- canvas 原语（`gfx/canvas.go`）：`fillRect / strokeRect / fillCircle / strokeCircle /
  line / drawText` + 路径（beginPath / moveTo / lineTo / closePath / fill / stroke / arc），
  线宽固定 1（`canvas.go` 注释：v1 不暴露画笔粗细）。
- `gx-datav` 里多处绕行注释：`sparkline.js` —— **「内核无 createLinearGradient」**，
  渐变只能用「多层半透明叠加」近似；`draw.js` 自己写 `vGradient` / `glowCircle` 模拟。

## 为什么难

1. **路径光栅化**：现在是折线近似，要上贝塞尔 + 解析式抗锯齿（覆盖率累加），
   纯 Go 下既要精度又要速度，还要与脏矩形裁剪共存。
2. **渐变 / 图案**：线性/径向/锥形渐变的采样与缓存，图案填充的变换与平铺；
   一旦允许任意渐变，颜色参数的解析与缓存键就要重做。
3. **滤镜**：阴影与高斯模糊是卷积，成本随半径平方增长；必须走降采样近似，
   而近似的视觉一致性要人眼验收（又是依赖 13 的地方）。
4. **图层与合成**：裁剪栈、蒙版、混合模式需要离屏表面，
   而离屏表面的生命周期与脏矩形失效是新的复杂度。
5. **契约边界**：canvas API 要对齐浏览器到什么程度？
   对齐越多，语义与测试成本越高（MDN 上一个小行为差异就是一条回归）。
6. **溢出失效**：特效（阴影/模糊）会画到节点盒之外，
   脏矩形必须包含溢出区，否则滚动后残留残影。

## 技术路线

1. 渐变（线性 / 径向）+ 多色停止点；
2. 裁剪栈与阴影（离屏表面 + 盒外失效）；
3. 路径抗锯齿升级（贝塞尔细分 + 覆盖率）；
4. 混合模式与蒙版；
5. 模糊（降采样近似）；
6. SVG 子集导入（路径 / 渐变 / 分组 / transform）。

## 验收标准

- 视觉样张与参考渲染的对比页（渐变、阴影、模糊、混合、裁剪各一张）；
- 盒外溢出不产生残影（滚动 / 重绘后像素比对）；
- 线宽与端点/连接样式语义写进文档并有回归；
- 帧预算不退化，特效可开关降级。

## 主要风险

| 风险 | 缓解 |
|---|---|
| 抗锯齿/滤镜与 CPU 光栅性能冲突 | 分档降级（无特效模式），性能闸门 |
| API 与浏览器语义不一致引发困惑 | 明确「子集 + 差异清单」并写进 `docs/` |
| 盒外失效漏改导致残影 | 结构化断言：重绘后区域像素稳定 |
