# 15 — 性能剖析与渲染管线工具链

- 分层：质量 ｜ 难度 ★★★ ｜ 工作量 3–6 人周 ｜ 依赖：—

## 现状取证（主仓）

- `gfx/frame_budget_test.go` 已有帧预算测试，`docs/performance.md` 有性能文档，
  `docs/mobile-perf-baseline.md` 有移动端基线。
- 但**没有 GUI 专用的分阶段剖析器**：现在是「整体有预算闸门」，
  出问题时不知道时间花在布局、绘制、命中还是脚本上。

## 为什么难

1. **分阶段计时不能污染时序**：剖析埋点本身会改变帧耗时，
   而「确定性单线程 + 帧预算」是这个项目的命脉——埋点必须是可开关、
   开销可忽略、且不影响事件与绘制顺序。
2. **脏矩形与重绘热点**：要能看出「这一帧重绘了什么、有没有多余的重绘
   （N+1 重绘、全屏脏）」，需要把脏矩形历史记录下来并可视化。
3. **缓存命中率**：字形掩码缓存（`gfx/font.go`）、位图缓存的命中率与失效次数
   是文字性能的关键指标，现在没有出口。
4. **把性能变成 CI 闸门而不抖动**：绝对阈值在共享 CI 上必然抖动，
   需要相对基线 + 容差 + 多次取中位数的策略，否则闸门会被随手关掉。
5. **与 VM 侧剖析打通**：脚本热点（字节码执行、GC/对象分配）与渲染热点
   要能在同一条时间线上看，否则只知道「慢」不知道「谁慢」。

## 技术路线

1. 分阶段计时埋点（布局 / 绘制 / 命中 / 脚本 / 上屏），可开关；
2. dev 面板与火焰视图（主仓已有 `dev.go` / `dev_console.go` 可挂）；
3. 缓存命中率指标（字形 / 位图）；
4. 重绘热点可视化（脏矩形叠加显示）；
5. CI 性能闸门（基线 + 容差 + 中位数）。

## 验收标准

- 任一界面可一键输出阶段耗时（有数值出口，不只是日志）；
- 人为引入「N+1 重绘」的回归能被闸门拦下；
- 字形缓存命中率可查询；
- 移动端基线达标（进 `mobile-perf-baseline.md`）。

## 主要风险

| 风险 | 缓解 |
|---|---|
| 埋点开销影响帧预算 | 默认关闭，压测与本地开启 |
| CI 性能闸门抖动 | 相对基线 + 容差，失败只警告不阻断（初期） |
| dev 面板与主线程竞争 | 只读快照，不在帧内做聚合 |
