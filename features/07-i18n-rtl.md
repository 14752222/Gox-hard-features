# 07 — 国际化与 RTL / 双向文本

- 分层：文本 ｜ 难度 ★★★★ ｜ 工作量 6–9 人周 ｜ 依赖：01

## 现状取证（主仓）

- 无 i18n 设施：没有 locale / 资源包 / 复数规则的内置支持（Temporal 提供日期时间，
  但 locale 化的格式化与文案外置不在仓内）。
- 布局无 RTL：自研 flex（`gfx/layout.go`）按声明序正向摆放，
  `layout.go:18` 明写**不支持 `order` / `alignSelf` / `align-content`**，
  镜像更没有。
- 文本按码位直排（`gfx/font.go`），没有双向算法，RTL 文本只能靠手动反转。

## 为什么难

1. **布局镜像不是「左右翻转」**：主轴起点/终点、`padding*`、`alignItems` 的
   start/end、图标与箭头方向、滚动条位置、命中测试与滚动方向全部要跟着翻，
   而自研布局引擎里每个摆放点都要改一遍。
2. **双向文本（bidi）**：逻辑顺序 ≠ 视觉顺序，英文数字嵌在阿语句子里是 LTR 段，
   光标移动、选区、截断（truncate）都要按视觉顺序——依赖 01 的 cluster 模型。
3. **CLDR 数据**：复数规则（zero/one/two/few/many/other，各语言规则不同）、
   日期/数字/货币格式、排序（collation），数据集体积与「单二进制」冲突。
4. **断行规则**：CJK 按字符断、拉丁按空格断、泰语需要词典——又是一份数据。
5. **热切换**：切换 locale 时不能重建界面（否则丢焦点、丢滚动位置、丢动画态），
   这是 08 的同类问题。
6. **资源外置与打包**：文案进包还是外挂？打包器（`packager/`）要不要支持语言分包。

## 技术路线

1. locale / 资源层（key → 文案，运行时查找，未命中回退）；
2. 格式化层（数字 / 日期 / 货币 / 复数，先小数据子集）；
3. 布局镜像（`dir` 属性 → 主轴反向 + 内边距/对齐映射 + 滚动与命中）；
4. 双向文本（借 01 的 cluster + bidi 段落级）；
5. 热切换（不重建树）+ 打包分包。

## 验收标准

- 阿语/希伯来语镜像界面截图：导航、列表、滚动条、图标方向全部正确；
- 复数与日期格式化用例（覆盖 zero/one/few/many 至少四种语言）；
- 切换 locale：焦点、滚动位置、输入内容均不丢（节点生命周期断言）；
- 混排文本（阿语中嵌英文数字）光标与选区按视觉顺序。

## 主要风险

| 风险 | 缓解 |
|---|---|
| CLDR 数据体积与单二进制冲突 | 按需子集 + 构建期裁剪，先只做 10 种语言 |
| 布局镜像改动面广 | 集中在 `layoutStack` 的起点/方向计算，不逐组件改 |
| 与 shaping 互相卡住 | 定义清楚：01 管「一段文本内部」，07 管「段与布局」 |
