# 06 — 跨平台 IME 与组合输入

- 分层：输入 ｜ 难度 ★★★★ ｜ 工作量 5–8 人周 ｜ 依赖：01、13

## 现状取证（主仓）

- `gfx/ime.go` 与 `gfx/x11/x11.go` 两处 `TODO(P2-7)`：Linux/X11 侧 IME 未接。
- `docs/v1-roadmap.md` P1-2：**「Linux/X11：IME 不支持 … 需走 XIM 协议」**——
  中文/日文用户在 Linux 下无法输入。
- 移动端（android / ios）另有一套软键盘链路，与桌面不是同一条代码路径。

## 为什么难

1. **协议层**：零 cgo 下实现 XIM（或 IBus）协议，等于在 X11 协议之上再写一层
   输入法协议，且**没有真机验证环境**时调试极其困难（主仓路线图里也把
   「Linux 实机验证」单列为 P1）。
2. **preedit（组合串）渲染**：组合期间的文本是「未确认」的，必须由自绘路径
   画出（下划线/背景标记），并且**光标位置、命中测试、文本宽度都要包含它**——
   与 01 的 textWidth / shaping 强耦合。
3. **候选窗**：需要跟随光标定位（跨屏边界翻转）、不能抢焦点、不能被自己的
   重绘逻辑清掉；本质上是一个「浮层 + 绝对定位」的组件，还要参与层级管理。
4. **时序纪律**：组合期每来一个事件都不应触发子树重建（否则输入会丢字/跳光标），
   这与「信号变化 → 重建子树」的现状直接冲突（见 08）。
5. **移动端**：软键盘弹起要避让（滚动到可见区 + 安全区），
   与桌面是同一套事件纪律的另一半实现。

## 技术路线

1. Linux XIM 通道（先能收 preedit 与 commit）；
2. preedit 渲染统一（下划线样式、光标包含组合串）；
3. 候选窗（跟随定位 + 不抢焦点 + 层级）；
4. 组合期重绘纪律（不重建子树，标脏即可）；
5. 移动端软键盘避让与安全区。

## 验收标准

- 三平台中文 / 日文输入往返（含中英混排、退格逐字删组合串）；
- 组合串与光标位置一致（截图 + 命中测试断言）；
- 候选窗跟随光标，跨屏边界不越界，不抢焦点；
- 组合期不丢字符、不触发子树重建（可用节点生命周期断言验证）；
- 移动端软键盘弹起时输入框可见。

## 主要风险

| 风险 | 缓解 |
|---|---|
| Linux 无真机验证环境 | 至少要有 xvfb + ibus 的 CI 冒烟；人工验收清单写明 |
| 组合期重建子树导致丢字 | 与 08 一起设计「组合期禁用重建」的开关 |
| 各平台 IME 行为差异 | 抽象出「preedit + commit + 候选」三事件，平台差异关在后端 |
